# P9. Baseline Profile - ahead-of-time compilation hints for the cold-start and first-frame path.
#
# Android Runtime interprets bytecode until a method is hot enough to JIT. A baseline profile
# names the classes and methods to compile at INSTALL time instead, so the first run is already
# native. Google's own case study on Maps reports ~30% off startup.
#
# The entries below are this fork's actual critical path, not a generic list:
#   - application start and the initialiser chain the first car frame waits on
#   - the Android Auto surface path, which is where a slow first frame is visible
#   - routing, because a reroute is the other thing the driver waits on
#   - the CairoDrive classes themselves, since they sit on every fix and every frame
#
# NOT generated from a device run - that needs a macrobenchmark module and a physical phone, and
# neither exists here. A hand-authored profile is strictly better than none (ART simply ignores
# rules that never match) but it is a starting point: regenerating it from a real run on the
# POCO C85 would target the actual hot methods rather than the reasoned ones.
